The screen's main question is: which unclaimed rewards do my current event points unlock? Existing identity includes the Clash of Critters mark, reward artwork, green calculator and game-like simulator. No project DESIGN.md exists. Before visual fixes, confirm whether to retain this identity. No replacement assets or navigation have been created.

## Numbered findings

1. **HIGH: Simulator dialogs and multiplier lack complete keyboard behavior. R-32, R-26.** Opened simulator > Rules > pressed Escape: the dialog remained open. Source has no Escape handler, focus trap or focus restoration; background calculator remains exposed. The multiplier uses pointer handlers only, so keyboard activation cannot cycle it. Fix dialog focus/dismissal and add keyboard-equivalent multiplier activation.

2. **HIGH: Touch targets are too small. R-03.** At 390px, calculator quick adjustments and Reset render around 30px tall. Simulator CSS defines Rules at 35px, dialog Close at 30px and multiplier at 29px tall. Give each a minimum 44px hit area and preserve spacing. Evidence: mobile-fold.jpg and CozyFarmPage.module.css.

3. **HIGH: Current-points input has no visible keyboard focus treatment. R-32.** App.css removes its outline with no replacement focus style for that input or its containing label. Simulator Support also removes its outline. Add visible focus indicators and verify the full keyboard path.

4. **HIGH: Loading failures have no recovery view. R-27.** Simulator lazy import has a Suspense loading screen but no error boundary/retry. Calculator localStorage writes are also unguarded, although reads are guarded; a write failure has no user feedback. Add local, useful failure feedback. The local calculator does not need an artificial loading spinner for synchronous calculations.

5. **HIGH: Lowering points can leave claimed progress above current progress. R-26, C-4.** Source inspection: setClaimedPoints clamps to current points, but setPoints does not reconcile claimedPoints or its displayed draft. A user can claim through 1,000, then lower current points to 100 and still see claimed-through 1,000. Define and enforce the intended invariant, with consistent input feedback. This is a source-confirmed path, not a browser reproduction.

6. **MEDIUM: Small, tracked monospace labels dominate the calculator. R-06, R-31.** Taste inspector measures seven tiny uppercase tracked labels and 61% of text below 13px. Screenshots confirm that instructions and adjustments are hard to scan. Keep figures readable, increase instruction/control text and reduce redundant labels. Main calculator also has no h1; add a useful screen heading without duplicating the event selector. Evidence: report.json and all three fold screenshots.

7. **MEDIUM: Shadows and gradients flatten the hierarchy. R-01, R-12, R-31.** All three resting panels carry stacked heavy shadows; the page, progress panel and simulator-launch control use gradients without a documented purpose. Taste inspector flags gradients, button effects and three heavy panel shadows. Retain the game's character through real reward artwork and selected accents, while reducing resting-surface effects. Confirm owner direction before changing the existing style.

8. **LOW: Tablet hierarchy wastes half of the next-milestone row. R-05, R-20.** At 768px the workspace stacks, but side-column still declares two columns for its single child. The next milestone occupies only half of its row and falls below totals. Make it full width in this band and consider positioning the next target nearer the points input. At desktop, the milestone title also wraps while the adjacent button stays on one line. Evidence: tablet-page-01.jpg and desktop-fold.jpg.

9. **LOW: Empty rewards state does not explain the next action. R-20, C-3; R-27 state-quality concern.** "Nothing new to total" does not distinguish zero points, being below the first milestone, or having already claimed everything reached. Explain the actual condition and point to the next milestone or claimed-through field. Source also keys this message to available.length, while Fishing can add recurring Glitter Fruit separately; check that edge case before changing copy.
